# WEP // УПУАУТ

WEP (Wepwawet ESP32 Profiler) — настольное приложение Windows для поиска
последовательных портов, запроса базовых идентификационных данных ESP32 и
сохранения профиля осмотра. Это практический инструмент диагностики, а не
универсальная система автоматического определения плат и периферии.

![Экспериментальный интерфейс WEP на Textual: порт обнаружен, но не подключён; профиль устройства отсутствует](./docs/images/wep-ui.png)

Это снимок экспериментального интерфейса на Textual. Порт обнаружен, но
подключение устройства и диагностика ESP32 не выполнялись, поэтому профиль
устройства отсутствует. Список портов относится к компьютеру, на котором сделан
снимок, и на других системах будет отличаться.

## Возможности

- Поиск и обновление списка последовательных портов Windows.
- Запуск операции esptool `read-mac` только для чтения типа чипа и MAC.
- Сохранение исходного вывода диагностики и различение успешного, частичного
  и неудачного результата.
- Сохранение профиля в JSON и экспорт таблиц CSV.
- Генерация текущего начального файла `platformio.ini`.
- Переключение интерфейса между русским и английским, тёмной и светлой темами.

Текущая диагностика не читает и не записывает flash, не определяет точную
модель отладочной платы, периферию, PSRAM или электрические свойства.
Сгенерированная конфигурация PlatformIO является шаблоном и требует проверки
для целевого устройства.

## Требования

- Windows 10 или Windows 11, x64 (Windows 11 не проверялась в текущей
  валидации).
- Python 3.11 или новее для запуска из исходников; проверенная сборка Windows
  выполнялась на Python 3.14.2.
- Tkinter/Tcl-Tk из стандартного установщика Python для Windows.
- Зависимости приложения из `requirements.txt`: pySerial и esptool.
- Необязательная зависимость экспериментального интерфейса Textual указана в
  `requirements-textual.txt`; для Tkinter она не требуется.
- PyInstaller 6.22.3 для проверенной сборки EXE; это отдельный инструмент
  сборки, не указанный в `requirements.txt`.

## Настройка в Windows

Выполните команды в PowerShell из корневой папки проекта:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Команды используют Python 3.14 для соответствия проверенной среде. Для запуска
исходников можно использовать Python 3.11+, однако совместимость других
сочетаний Python и PyInstaller здесь не сертифицирована.

Для запуска WEP из исходников PyInstaller не нужен. Для сборки EXE установите
проверенную версию инструмента отдельно в `.venv`:

```powershell
.\.venv\Scripts\python.exe -m pip install PyInstaller==6.22.3
```

## Запуск из исходников

```powershell
.\.venv\Scripts\python.exe run_wep.py
```

Для отдельного экспериментального интерфейса Textual установите его набор
зависимостей и запустите отдельную точку входа:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-textual.txt
.\.venv\Scripts\python.exe run_wep_textual.py
```

Обычный запуск `run_wep.py` по-прежнему открывает Tkinter. Textual-прототип не
включён в сборку Windows EXE.
В панели экспорта Textual укажите путь к JSON- или INI-файлу и существующую
папку для CSV; если расширение `.json` или `.ini` не указано, оно добавится.
Перезапись существующих файлов требует подтверждения.

## Сборка Windows EXE

Собирайте из корня проекта. Если папки из примера уже содержат чужие результаты,
выберите новые каталоги, чтобы не перезаписать их:

```powershell
$distPath = 'dist\WEP_Redesign'
$workPath = 'build\WEP_Redesign'
if (Test-Path $distPath) {
    throw "Папка результатов уже существует: $distPath. Выберите свободный путь."
}
if (Test-Path $workPath) {
    throw "Рабочая папка уже существует: $workPath. Выберите свободный путь."
}
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --distpath $distPath --workpath $workPath WEP_Copilot.spec
```

Проверенная сборка создала `dist\WEP_Redesign\WEP.exe` с PyInstaller 6.22.3.
Конфигурация создаёт один самодостаточный EXE. Запустите его и убедитесь, что
открывается GUI: одного успешного завершения сборки для подтверждения запуска
недостаточно.

## Подключение и диагностика ESP32

Подключите плату, закройте другие программы, использующие её последовательный
порт, обновите список портов, проверьте выбранный COM-порт и запустите
диагностику. esptool может сбросить плату. GUI использует `default-reset` перед
`read-mac` и `hard-reset` после; некоторому оборудованию может потребоваться
ручной BOOT/RESET. Автоматические тесты и проверка сборки не означают, что
физическая плата диагностировалась.

Результат содержит только данные, фактически полученные диагностикой. См.
[описание диагностики](./docs/DIAGNOSTICS.ru.md) со статусами, ошибками,
тайм-аутами и поведением reset.

## Отчёты и конфигурация

Сохраните JSON текущего профиля, экспортируйте CSV в существующую папку
(`profiles.csv`, `devices.csv` и `observations.csv`) или создайте
`platformio.ini`. Текущий файл PlatformIO содержит заранее заданное окружение
`RONGO_node` и `board = esp32dev`; перед сборкой прошивки проверьте их
соответствие реальной плате.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют моки последовательных портов и диагностических процессов.
Они не подтверждают подключение физической ESP32 или автоматический вход в её
загрузчик. В репозитории пока не настроен линтер или форматтер. Тесты
интерфейса Textual запускаются при установке его необязательных зависимостей;
без них эти тесты пропускаются.
