# Настройка разработки

Для WEP используется виртуальное окружение проекта `.venv`. Из корня проекта
выполните в PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Для запуска всех тестов:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Для запуска графического приложения:

```powershell
.\.venv\Scripts\python.exe run_wep.py
```

Интерфейс использует стандартные Tkinter и ttk. Цветовая тема и язык интерфейса
сохраняются в `%LOCALAPPDATA%\WEP\settings.json` и не попадают в репозиторий.
Для новых установок язык интерфейса по умолчанию — English; язык можно изменить
в самой программе без перезапуска.
Если у установленной сборки Python отсутствует Tkinter, установите обычную
Windows-сборку Python с компонентом Tcl/Tk и повторно создайте `.venv`.

Тесты обнаружения последовательных портов используют моки и не требуют
подключённого оборудования.

Диагностика ESP32 использует `esptool==5.6.0` в отдельном процессе с тайм-аутом
20 секунд. Она запрашивает тип чипа и встроенный MAC через `read-mac`, не читая
flash и не выполняя операции записи или стирания. Перед запуском диагностики
плата может быть сброшена, что прервёт выполняющуюся прошивку. Автоматический
вход в загрузчик зависит от платы; если он не сработает, следуйте инструкции
BOOT/RESET и повторите попытку вручную. Повтор выполняется без переключения
линий сброса; после успеха плата сбрасывается в обычный режим загрузки.

Тесты диагностики используют моки дочернего процесса и не требуют платы.
