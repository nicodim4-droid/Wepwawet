# Руководство пользователя

WEP (Wepwawet ESP32 Profiler) — настольная программа Windows для поиска
последовательных портов и сбора ограниченного идентификационного профиля
ESP32. Интерфейс доступен на русском и английском языках; можно выбрать
тёмную или светлую тему.

## Запуск WEP

Для запуска из исходников см. [документацию разработки](./DEVELOPMENT.ru.md).
Для запуска упакованной версии откройте самодостаточный `WEP.exe`, созданный
PyInstaller в режиме сборки одного файла.

## Выбор последовательного порта

В разделе `TARGET` показаны порты, обнаруженные Windows через pySerial. Если
операционная система предоставляет эти данные, рядом могут отображаться
описание порта, USB VID/PID или серийный номер. Выбор порта сам по себе не
открывает его и не подтверждает подключение ESP32.

Нажмите **Обновить список** после подключения или отключения платы. Выберите
нужный порт. WEP первоначально выделяет первый обнаруженный порт, поэтому
перед диагностикой проверьте выбор.

## Запуск диагностики

Подключите плату по USB и закройте другие программы, которые могут использовать
её последовательный порт. Выберите порт и нажмите **Запустить диагностику**.
Операция выполняется вне цикла событий Tkinter. Через операцию esptool
`read-mac` запрашиваются тип чипа и MAC; плата может быть сброшена. Прошивка
устройства не записывается.

GUI использует `default-reset` esptool перед диагностикой и `hard-reset` после
неё. Некоторые платы автоматически не входят в ROM-загрузчик. При ошибке
прочитайте рекомендацию и подробный вывод esptool. Если плате нужен ручной
BOOT/RESET, следуйте указаниям производителя. При этом повторный запуск из GUI
всё равно использует `default-reset`: отдельного режима `no-reset` в GUI нет,
поэтому reset может вывести плату из загрузчика. Перед поиском причины см.
[описание диагностики](./DIAGNOSTICS.ru.md).

В результатах различаются успех, частичные данные и ошибка. Отображаются
только значения, фактически извлечённые из ответа устройства. Включите
**Подробный вывод esptool**, чтобы просмотреть исходный вывод. Кнопка
**Копировать результат** помещает в буфер обмена читаемый отчёт.

## Сохранение и экспорт

- **Сохранить JSON** открывает диалог выбора файла и сохраняет текущий профиль
  по схеме версии 2. JSON содержит идентификатор профиля, время создания,
  наблюдаемые значения, их происхождение/достоверность, предупреждения и
  ошибки.
- **Экспорт CSV** предлагает выбрать существующую папку и создаёт в ней
  `profiles.csv`, `devices.csv` и `observations.csv`.
- **Создать platformio.ini** сохраняет текущую начальную конфигурацию программы
  в выбранную папку. Если файл `platformio.ini` уже существует, WEP спрашивает
  подтверждение перезаписи.

Файл PlatformIO является шаблоном, а не выводом конкретной модели платы. Сейчас
в нём используются `board = esp32dev` и предварительно заданное окружение
`RONGO_node`. Перед сборкой прошивки проверьте плату, платформу, библиотеки и
остальные параметры.

## Язык, тема и настройки

В верхней панели выберите **Русский** или **English**, чтобы переключить язык
без перезапуска. Рядом доступен выбор тёмной или светлой темы. Оба значения
сохраняются в `%LOCALAPPDATA%\WEP\settings.json`.

## Что WEP не определяет

WEP не распознаёт автоматически точную модель отладочной платы или подключённую
периферию. Текущая диагностика считывает только тип чипа и MAC; она не проверяет
flash, PSRAM, прошивку или электрические параметры. Отсутствующее значение не
означает ноль или подтверждённое отсутствие свойства.
